**尚未正式啟用。** 以本次使用者貼出的 v1.0 修改，不是快速準備包的第二套寫入器。正式 Apps Script 編輯器／觸發器權限仍不可用，依指示未重試登入。使用者已批准加速，無須再次要求同一批准；main／Streamlit 不在本次授權內。

可完整貼上：`FCN_price_updater.gs`。`FCN_price_updater.original.gs` 是使用者提供程式的可執行備份（只壓縮格式與註解），**不是從正式專案匯出的備份**。不要把兩個檔案同時放入 Apps Script。

## 最短操作

1. 用原觸發器擁有者帳號，於原股價庫「擴充功能 → Apps Script」，下載／複製現行程式與觸發器設定留存。確認唯一寫入器為 `FCN_hourlyJob`，其他帳號／專案及 GitHub 更新器也沒有同時寫入。
2. 先在**隔離副本**貼上最終程式；只將 `FCN_CONFIG.SPREADSHEET_ID` 改為副本 ID。保持中央庫 ID 不變（只讀）；執行 `FCN_install`。確認來源可用、日期／價格讀回成功、原歷史價格不變，並在觸發器頁看到唯一 `FCN_hourlyJob` 每五分鐘。測試副本驗證完執行 `FCN_stop`。隔離副本不是第二套正式行情庫，不供網站讀取。
3. 正式專案確認沒有執行中的舊工作，**用最終程式取代原檔內容**（不要加掛準備版）；保留正式股價庫 ID，執行一次 `FCN_install`。它在鎖內先驗證來源／中央優先股讀取權限，再移除本帳號同函式舊觸發器、建立一個五分鐘觸發器；不清除舊游標或未完成暫存。檢查觸發器確實只有一個。
4. 首輪後看 `FCN_同步狀態`、`更新紀錄`、原 `收盤價矩陣`：核對 AAPL/NVDA/AMD/TSLA/MU 的**交易日期及數字**，比較歷史價未變；記錄實際首輪耗時。遇來源尚未算好、授權錯誤或讀回失敗，不得稱為上線成功。

## 修改界線

- 保留 `FCN_hourlyJob`、LockService、原庫與原三個暫存／狀態分頁、`copyTo(PASTE_VALUES)` 轉快照路徑。不使用準備版的直接讀歷史公式方案。
- 每次讀入最多40檔，使用一個每五分鐘週期觸發器，無接力觸發器堆積。180秒合作式時間檢查，超時保留游標；單次 Google 呼叫本身的耗時仍受平台控制。
- 原暫存／快照頁擴充為各批固定100列區塊（通常14批，舊未完成批次不足40檔時最多15批）。未完成公式與結果**不清除、不覆寫**；其他批次能前進。既有 `PROPS_STAGE` 首批保留。每日最多三輪，缺價留白，下一交易日透過原27天回看視窗繼續檢查。Google 公式是否重算由 Google 決定，腳本重讀並非保證供應商重新計價。
- 修正優先順序造成的非連續欄位寫錯風險：以原矩陣股票欄名定位，排序後只寫空白連續區塊，立即讀回；即使零或錯誤文字也不自動覆蓋。失敗重跑不重寫已有值。
- 日更起點為美東正常收盤後5分鐘；已列入的提前收盤日為13:05。時區轉換處理夏令時間。週末與NYSE休市排除；修正準備包把2027-12-31誤列為新年補休的問題。日期只接受有效日曆日，價格只接受有限正數。來源晚一天、空值、字串、布林均不冒充當日收盤。
- 優先順序來自中央條款的未過期／缺期末日商品連結股；未知日期保守保留。**中央沒有可信的最新 V2 KO 同步欄，因此這是監控股票的保守超集，可能多含已提前KO但未到期商品**，不重寫一套KO引擎，也不使用中央 latest_close。每日重排含優先股的批次；既有未完成區塊不為改序而覆蓋。
- 為保護未完成區塊，這版的手動90天重建入口明確停止並提示另案處理；不假裝修改屬性便已重建舊公式。切回原版可恢復原手動補價流程；一般27天缺價重試仍保留。

## 回復原每小時排程

執行 `FCN_stop` → 確認執行紀錄已無工作進行中 → 貼回步驟1保存的正式原碼（或核對後使用原版備份）→ 執行原 `FCN_install` → 確認只剩一個每小時 `FCN_hourlyJob`。原矩陣及已固定歷史不回滾、不刪除；新暫存區塊可保留。若安裝建立觸發器失敗，也依此恢復原排程。請勿同時啟動 `fcnFastTick` 或 GitHub 寫入器。
